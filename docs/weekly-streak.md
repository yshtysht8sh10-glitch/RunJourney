# 週間目標・週間継続Streak（Issue #10改訂）

2026-10-17更新のIssue #10に対応。メイン指標を「今週の達成走行日数 / 週間目標」「連続達成週数」「最高連続達成週数」へ変更した。毎日走ることを求める文言、今日あと何kmという促しを削除し、日次Streakは詳細内の折りたたんだ参考値とする。

## 計算と設定

- 共通ロジック `src/domain/weekly-streak.ts` はRunRecordまたはRunSummaryから再計算する。Webは既存のメタデータだけを渡す。GPSの追加読込・保存形式・同期形式・走行原本に変更はない。
- 初期設定は週4日、1日のEffective距離合計1km以上、追加時間条件なし、月曜始まり。日数1〜7、距離、実走時間、開始曜日はWeb Settingsで変更できる。時間条件を設定した場合は距離と時間の両方が必要。正の距離条件を必須にしてゼロ距離記録だけの達成を防ぐ。GPS誤差の除外は既存Effective Run計算を使用し、閾値だけで誤差を完全に排除できると保証しない。
- 同日の複数Runを距離・実走時間ともに合算し、達成日として1回数える。ごみ箱、読み出しエラーの記録、将来開始の記録は除外する。
- タイムゾーンはWeb既存設定を使う。日を跨ぐRunは全量をSTART日の現地日付に計上する。週は現地の暦日と設定した開始曜日で分類し、週の最終日の後に確定する。DSTの24時間長短に依存せず暦日キーを計算する。
- 進行中の今週が未達でも、直前の確定週までの週間Streakを保持する。今週早期達成なら今週を加算する。未達の週が終了すると、その週で継続が途切れる。過去最高は現在までに達成した週列から計算する。
- 達成後の残りの日に記録がなくても、その週の達成を取り消さない。痛み・疲労がある日は休養を優先する案内を表示する。
- 設定変更は過去を含む全履歴を現在の設定で再評価する。これは設定画面とStreak画面の両方で明記した。履歴変更・ごみ箱移動・同期取得後も同じ計算を使う。
- 設定はRunRecordと分離し、ブラウザの `runjourney-weekly-goal-v1` に保存する。別端末への設定同期・Native設定画面は今回未実装。計算ロジックはNativeからも利用可能。

## 表示

DashboardのカードとStreakの主画面は週間表示。達成カレンダーは✓達成走行日、○走行記録あり・条件未達、·未記録、—未来を区別する。休養登録UIは未実装であり、「未記録＝休養」と断定しない。将来休養登録を追加する場合はRunRecordから分離した明示データを使う。

日次の現在・最高値は「参考：日次Streak（距離基準）」として残し、週間の追加時間条件は適用しないことを表示する。日次の通知・ペナルティは設けない。既存Gamification ON/OFFを維持し、通常の記録画面を変更しない。

## 検証

追加テストは、週4日/3日、週途中/週終了、間隔の空いた走行日、達成後の未記録日、同日複数Run、1km未満、追加時間条件、START日帰属、UTC/Asia-Tokyo、月曜/日曜境界、設定変更による過去再評価、編集/ごみ箱/エラー/将来記録、空履歴、不正設定を対象とする。日次Streakが切れても週間で2週連続達成するケースを含む。

実機・本番Firebase・救出原本には適用していない。保存/ページ同期の安全な既存成果は維持した。

検証コマンド: `npm test -- --silent` / `npm run lint` / `npm run typecheck` / `npm run web:build`。ブラウザでは週4日→6日の変更による過去再評価・週途中の継続保持、週4日への復帰、日次参考欄の展開を確認した。

結果: 週間Streakの追加18件を含め、Jest 30 suites / 288 passed / 0 failed。lint・型検査・Web export成功。既存のnoble内部exportに関するMetro fallback警告は継続している。
