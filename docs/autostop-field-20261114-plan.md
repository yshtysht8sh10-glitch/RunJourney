# 11月14日（土）7km走：独立マーカー設計と評価計画

2026-11-12作成。**設計のみ、未実装・未検証**。同行者/別端末/腕時計はないとの回答を反映し、普段使うShokz OpenComm2の多機能ボタンを第一候補とする。11/12の13停止は正解ラベルに転用しない。Auto Stop判定/通常RUN保存/GPS頻度を変更しない。

## 1. OpenComm2は使えるか

メーカー公式説明書では多機能ボタンの1回押しが再生/一時停止。ミュートは通話用、音量は機器設定を変えるためマーカーに流用しない。[Shokz OpenComm2公式説明書・8～9ページ](https://userguide.shokz.net/upload/user/20261106/700e3470ec74fc54832c3dc1a55bda1b.pdf)

AndroidはBluetoothメディアボタンをKeyEvent/MediaSessionへ配送する仕組みを持つ。しかしRunJourneyには現在MediaSession/メディアボタン受信がなく、OpenComm2＋このTest端末で画面OFF/無音中にも届くか未検証。MediaSessionを作れば必ず届くとは保証しない。他の音楽アプリや通話、2台同時接続も競合要因となる。[Android公式のメディアボタン配送](https://developer.android.com/media/legacy/media-buttons)

**結論：マーカーに利用できる可能性がある。Test限定実装と実機ゲートを通す前に「使える」とは扱わない。** 常時音声認識/連続マイク録音/HFP強制への切替は提案しない。音声出力・騒音計測との競合や電池負荷を避ける。

## 2. 操作案と独立性

開始前だけスマホで「実停止マーカー（実験）」を明示ONし、試し押しとマーカー台帳の受信を確認する。新機能の初期値はOFF、Test package完全一致限定。実RUN開始は既存STARTのみ。

走行中の案：

1. 1km通過は停止するきっかけにするだけ。音声が遅れたり安全な場所でなければ先へ進む。
2. 実際に足を止めた直後、多機能ボタンを1回押す（自己申告STOP）。
3. 安全な場所で20～30秒程度静止する案。停止通知が鳴ったことを再開条件にせず、判定と独立した予定で走り出す。
4. 走り出す最初の動作に合わせて1回押す（自己申告RESUME）。
5. 約1kmごとに反復し、7km付近の最後の再開後に通常STOPで終了する。

押す操作は同じでもラベルphaseはマーカー専用台帳のSTOP→RESUMEで交互にする。**Auto Stopの状態を見てラベルを選ばない**。RUNタイマーの停止/再開やGPS保存をボタンから呼ばない。phaseずれは検出器で自動補正せず、原マーカーを残したappend-only注記で「押し忘れ/誤押し/ラベル不明」を付ける。

これはGPS/Auto Stopとは独立した**自己申告参照時刻**であり、映像で確認した厳密な身体停止時刻ではない。反応・ボタン位置・Bluetooth配送の誤差を含む。独立性と時間精度は別々に評価する。

## 3. 時刻・重複・受信契約

- Nativeのキー受信時に、key action/code/repeatCount、eventTime/getDownTime、受信uptime/elapsedRealtime/wall time、boot/session ID、markerSeqを採る。機器名は固定の種別名のみで、MAC/GPSは採らない。
- `KeyEvent.eventTime`はuptime基準で、elapsedRealtimeはdeep sleepを含む。混同して引算しない。epochへの変換に使ったanchorと不確かさを保存し、受信時刻を機器内の物理押下時刻と同一視しない。[KeyEvent資料](https://developer.android.com/reference/android/view/KeyEvent#getEventTime())、[SystemClock資料](https://developer.android.com/reference/android/os/SystemClock)
- マーカーをNative専用workerへappendし、通常RUNのSQLite transactionを待たない。原seqは順序付き、時刻の事後上書きなし。本文の再生待ちでも入力は受け付ける。
- 生KEY_DOWNを1回だけ処理し、repeatCount>0/対応KEY_UPはマーカーにしない。raw handlerとonPlay/onPauseの二重処理を避ける。PLAY/PAUSE/PLAY_PAUSEの実際の配送形は試験で確定する。型だけ異なる重複イベントはdownTime/device-local event keyで照合し、意図的な別押下まで広いdebounceで消さない。
- 受信ACKはphone振動/画面カウンターを基本案とし、短い耳元の確認音を足すなら正式停止音声を中断しない別レビューとする。OpenComm2自身のbeepは端末保存ACKの証拠ではない。
- 通話中、別アプリへ配送、Bluetooth切断、process kill等はmarker availability gapとして表示する。取得できなかった間をGPSで埋めない。再接続後の最初のphaseが不明ならUNKNOWNとし、RUN後の確認を求める。
- Test RUN中・明示ONだけメディアセッションを使い、終了/明示OFFで解放する。メディアキーを奪うための無音トラック常時再生や虚偽のPLAYING状態は使わない。押下をSTART/STOP/音量/音声停止へ転送しない。

## 4. 実機採用ゲート（承認後）

|検証|合格条件|
|---|---|
|前景→無音・画面OFF→15分待機後|各条件10押下、端末保存数が物理押下数と一致。重複0、phaseずれ0。回収ログで確認|
|TTS本文/チャイム中|各10押下、marker保存、案内の不必要な停止0。キーイベント処理と音声再生を独立化|
|誤操作|長押し/repeat/ダブル押し/volume/mute/着信/切断の理由が記録され、正常RUN状態を変えない|
|時刻|Native受信→append queue p95目安100ms以下。キーeventTime→受信差を別集計。実際の押下/身体動作からのBluetooth・人間誤差は測れていなければ不明|
|画面OFF通常RUN経路|Testの隔離人工入力でAuto Stop/events/SQLite結果がOFF時と一致。実機RUNは別承認と保全後に実施|
|保全|元RUN/GPS/ごみ箱/設定/グループ/保護情報不変、11/12診断file hash不変|

無音時に届かない/他アプリの再生を起動する場合は採用不可。OpenComm2を初期化・ペアリング解除・音量変更して強行しない。採用失敗なら7kmは通常RUNの観察試験に縮小し、Auto Stopの身体停止精度は未検証とする。スマホ画面の手動マーカーは任意の代替であり、毎回操作を前提にしない。

## 5. 診断・RUN設定の事前案

7kmをAuto終了目標にすると最後の停止後の再開を記録できない場合がある。**終了方法は手動、7kmは走行目安**を推奨する。ペース走の距離/目標ペースは必要ならそのまま使う。既存設定を開発側で無断変更せず、前日レビュー後に操作手順で指定する。6kmまでの6組だけを主評価にし、7km終端は別枠にする代替もある。

既存診断はSTART前にARMED確認、95分/容量上限はそのまま。7kmでも95分内に終わると仮定せず、診断の採取区間だけリプレイ対象にする。診断が終わってもマーカー/音声ログは独立したRUN終端まで続ける設計。今回新しいマーカーを11/12のseal済みjournalへ追記しない。

更新が必要なら既存全データ・診断file hash・旧APK・署名・新hashを保存してからTestだけ更新。元履歴の復元/削除、期限削除API、ごみ箱画面の保持期限処理を呼ばない。端末の解除が必要なら本人へ依頼する。実走後もまず読み取り/バックアップ、検証RUNの片付けは別承認とする。

## 6. ラベル対応と評価式

1kmラップは独立マーカーに後付けで「何km付近」を対応させる補助情報のみ。停止時刻を距離境界に置き換えない。音声ラップの再生時刻も距離境界の正解時刻ではない。

主解析前に対応規則を固定する案：有効な自己申告STOP～RESUME組に対し、停止確定はSTOP前3秒～RESUME直前、再開確定はRESUME前3秒～20秒後の窓で時間順に1対1対応。窓外も消さずunmatchedとして一覧にする。3秒は操作誤差の感度分析用の暫定値で、実測した誤差を装わない。±0/±1/±3秒で評価が変わるか併記する。

|項目|報告する値/扱い|
|---|---|
|停止検出遅延|event.confirmedAt−STOP marker。event.timestamp−markerも推定開始差として別記。負値もそのまま|
|再開検出遅延|event.confirmedAt−RESUME marker。同様に推定/確定/JS受信/Native音声開始を分離|
|意図停止の見逃し|有効なSTOP～RESUME組で対応停止がない件数。marker不完全組は分母外|
|走行中の誤停止|自己申告上RUNNING区間に未対応停止がある候補件数。自然停止や押し忘れを本人確認してから確定。連続映像がないので全RUNの真の誤停止率とはしない|
|再開の誤判定|自己申告STOP区間中の再開/短期反復を列挙。ボタン誤差範囲内は判定保留|
|通知|各対応eventの生成/受付/チャイム/本文開始/完了/中断理由、推定開始→確定→本文の遅延。聴取成功は本人の記憶回答と別|
|保全|既存snapshotとfile hash、今回RUNの最終保存、GPS配信/採用/SQLite/診断の各件数、診断終了後継続|

7組程度なので遅延は全件値と中央値/最大を中心に報告する。小標本p95や正確率を過大解釈しない。自己申告以外の独立映像がないため、反応/通信の誤差より細かい真の検出遅延は結論づけない。

## 7. 承認後の簡潔な利用手順の雛形

1. Test版/バックアップ済み表示を確認。診断ARMED、Auto Stop ON、マーカーON、終了方法を確認。
2. OpenComm2を接続し試し押し。受信が増えることを確認して本番phaseをRUN開始時に新規化。
3. 通常START。安全な1km付近で止まったら1回、走り出すとき1回。止まれない場所では無理に止まらない。
4. 最後の再開後に通常STOP、保存成功を確認。診断/音声/マーカーは削除しない。

この手順は未搭載機能を含むため、現行v32でそのまま実行できる手順書ではない。受信可否・レビュー・実装・APK・実機確認が揃ってから確定版を渡す。
