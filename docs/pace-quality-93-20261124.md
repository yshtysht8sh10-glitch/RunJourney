# #93：PACE数値案内の復帰（2026-11-24）

対象：Test v37 `9a9ee26` / main `2ca976c`。両SHAのPACE/GPS入力/品質処理は同一。#48・#78・PR #91の3時間試験と関連。本人の11/24実走データは取得していないため、そのRUNの個別トリガーは未特定。通常5分・1km案内は正常だったという本人の観察と、コードで確認した原因を区別する。

## 原因として再現した事実

従来PACEは開始から各境界までを毎回検証し、一度の開始GPS遅れ・精度20m超・10秒超gap等を後続の全区間へ伝播させた。通常距離計算は50m以内などの既存条件で有効な辺を積算するため、普通のラップが計算できてもPACEだけ不足になる。20秒の受信遅延も15秒の境界待機後に不足として確定した。既存の混合3時間試験は179区間中7区間のみ数値、172区間不足だった。

## 本人が決定した仕様と実装

- 累計貯金秒＝目標sec/km×有効距離km−累計実走秒。`effectiveEdges` / `timeModel`を再利用し、Auto Stop・手動休憩・保存距離の条件を変えない。
- `pace-evidence.ts`は受信済みの実GPS辺だけを使う。未来時刻の点は辺を遮断し、除去による隣接辺の捏造もしない。遅延到着済みで正しい順序の点は利用できる。順序/時計破綻は数値成功扱いしない。
- 区間値と累計値を独立させる。精度20m/10秒gap等の従来追加検査は品質注記であり、50mの共通距離フィルターを緩和しない。異常辺を埋めない。保存・GPS・Auto Stopの閾値は変更しない。
- 区間数値不足でも累計が計算できれば案内する。累計は概算なら「約」、区間増減は「概算」と明示する。良好区間へ戻れば区間品質も回復する。
- 境界から最終有効GPSが60秒以上離れる、又は補間の両端間隔が60秒超なら、古い累計を現在値とせず最終有効時点の実走時間を発話する。60秒は音声の鮮度表示基準のみ。GPS採用・Auto Stopには使わない。長い辺も既存距離モデル以上の架空距離へ増やさない。
- 鮮度は通知対象境界を基準とする。後でGPSが途絶えても過去の正常境界を巻き戻さない。Native受理済みsnapshotは従来どおり永続ACKで固定する。
- 根拠のあるGPS対・有効時計がない場合のみ「累計は不明」。ゼロ移動の実測は距離0であり欠測ではない。全休止/設定変更取消・15秒待機・候補待機・32件上限・Native優先度/TTL/保存形式は維持。
- READYは再生可能な累計数値を意味する。追加の`intervalNumeric/cumulativeNumeric`、`intervalQuality/cumulativeQuality`、`asOfAt/qualityReasons`で品質を区別する。既存version1/quality列挙との互換性を維持。座標を音声診断ログへ追加しない。

変更：`src/domain/pace-evidence.ts`、`pace-periodic.ts`、`src/utils/distance.ts`（既存判定の関数抽出）、`src/services/voice-announcement.ts`（品質メタデータ）、private CLI/試験。通常ラップ文面・音声キュー・Native・RUN保存コードの変更なし。

## 検証と受入

固定SHAの独立レビューおよび最終の集計結果をPRへ記録する。関連テストは連続5秒GPS、開始遅れ、短い欠測、20秒遅延、40m/不良精度、回復、異常位置/逆順/未来点、長い欠測、停止/再開、ACK再試行を含む。合成入力は実GPS/実機再生の成功と扱わない。

private CLI：`node scripts/gps-private.cjs synthetic 180 <リポジトリ外の新規report.json>`で従来混合試験、`continuous 180`で正常5秒間隔試験。実データ取得は不要。集計は座標なし。`paceNumeric.intervalRate/cumulativeRate`を別々に確認し、静止取消等を除く対象件数とSTALE件数も示す。保存GPS件数・Auto Stop結果も旧集計と比較する。

端末データ操作・APK更新・本人GPS取得・Production配布なし。実機音声・電池/負荷は未検証。#93はmainへ統合してもOpenを維持し、本人の次回実走で累計数値が継続して読まれることを最終受入とする。
