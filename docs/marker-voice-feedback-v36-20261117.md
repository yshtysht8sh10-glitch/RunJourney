# Test v36：Shokz向け保存ACK音声フィードバック

Draft PR #77。基点5a28b47、前回検証資料は[sensor-reliability-v36-20261116.md](sensor-reliability-v36-20261116.md)。この変更は診断用の状態/保存結果のみを音声へ渡す。センサー値、Auto Stop判定、GPS要求、通常RUN保存を変更しない。

## 音声と保存の契約

| イベント | 本文 | 発生条件 |
| --- | --- | --- |
| SENSOR_STARTED | センサー記録を開始しました | 両ストリームの実サンプルでRECORDING成立。ARMED/登録だけでは生成しない |
| BEGIN_SAVED | マーカー開始 | protocolのMARKERとACKの書込み・fd.sync成功後 |
| END_SAVED | マーカー終了 | 同上。保存済み通番の偶奇からラベルを確定 |
| MARKER_FAILED | マーカーを記録できません | 実受付拒否・状態再確認拒否・保存失敗。キーUP/重複DOWN/リピートは発話しない |
| SENSOR_STOPPED | センサー記録が停止しました | 開始失敗・途中停止・書込み失敗・プロセス再生成時の失敗検出。通常RUN終了は対象外 |

音声はACK自体ではない。MARKERだけでACKに失敗した場合は成功音声を生成せず、不完全なファイルを残す。拒否/失敗でBEGIN/ENDを進めない。音声失敗を保存処理へ返さず、保存済み記録を取り消さない。

押下のwall/elapsed/uptimeとキーの取得可否を維持。ACK内wallは書込み開始時刻と明記し、音声メタデータとMARKER_SAVEDのsavedAt/savedElapsedはACKのfd.syncが戻った後に取得する。遅延再生でも両時刻を置き換えない。センサー側LABELは別の非同期記録であり、マーカーACK成功をLABEL永続化まで保証したことにはしない。終了後に両方を認証する。

## 既存音声への統合

別のTTS/MediaPlayer/MediaSessionを作らず、既存RunAnnouncerServiceへTest専用actionで投入。batchのRUN/停止状態/時計設定は更新しない。

- 種別TEST_DIAGNOSTIC_FEEDBACK、優先度25。既存のRUN開始終了・停止候補/確定再開・ラップ・時計より低く、PACEより高い。新通知から既存通知を中断しない。新チャイムなし。
- 通常の16件キュー枠を消費せず、新種別だけ32件上限。成功は個別に追跡。すでに待機/発話中のマーカー失敗警告は統合し、統合先IDをログへ残す。センサー停止はセッションごとの固定IDで1回。
- session/押下IDをseenに記録して重複を除外。重要な状態通知に割り込まれた場合は同じIDのまま最大2回再待機。完了済みを再生成しない。TTSエラー後の無条件再発話は行わない。
- 新種別に配送TTLは設けない。RUN終了・センサーsession変更・マーカーsession変更で取消。開始音声は現在もRECORDINGのときだけ有効。古い音声の終了後再生を防ぐ。
- 本文は既存の音声フォーカス・TTS経路と30秒watchdogを共用。短文でも独自の5秒完了期限で中断しない。音量・Bluetooth経路を強制しない。画面OFF用の既存wake lockを共用し、RUN音声停止中のTest単独配信は最大120秒。
- 既存時計は他音声/待機通知を理由にスキップする。新Test通知だけが再生/待機している場合は時計を待機させ、優先度30で新フィードバックより先に再生する。元の周期/5秒TTL/文面/通常音声同士の競合条件は変更しない。新通知の追加による時計欠落を避けるためのTest専用統合。

音声はbest effortであり、フォーカス拒否・TTS初期化失敗・再生エラー・上限・サービス死等はログで失敗を区別する。Native DONEはShokzから聞こえた証明ではない。

## ログ・保全

FEEDBACK_GENERATED/DELIVERY_FAILEDを既存の独立暗号化状態ログに記録。音声側はID・種別・押下/保存/生成/キュー/開始/完了・中断/統合/取消/失敗を対応付ける。原GPS/経路/生センサー/鍵を追加しない。

新Test音声保存先voice-log-feedback-v36へ分離し、voice-log-reliability-v36を含む既存記録を保持期限処理から分離。診断/マーカー形式・保存場所・暗号認証は維持。既存の保存データを削除/復元しない。
