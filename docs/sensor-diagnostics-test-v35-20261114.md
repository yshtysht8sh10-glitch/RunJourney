# Test v35 センサー診断 — 実装・検証記録

PR #76のTest v34を基点とする別ブランチ。Auto Stop判定・GPS要求条件・SQLite保存・音声キューの変更なし。
加速度とジャイロは診断ファイルだけへ保存し、判定や音声へ渡さない。Production/PaceではNative packageガードにより開始不可。

## 実装

- 初期OFF、1RUNだけARMED、装着位置（腰ポーチ/ポケット/手持ち/腕/その他）を記録。
- 25Hz要求、Native専用HandlerThread、2秒ごとの暗号化書込み、UIへは集計のみ。
- イベント時計/受信時計を別保存。実Hz、間隔p50/p95/max、80ms超ギャップ、欠測推定（正確なOS欠損数ではない）、時刻逆転を集計。
- SDK57/expo-location 57.0.20固定のTestビルド限定パッチで、同じLocationへelapsedRealtimeNanosとシリアライズ時刻を追加する。新しいGPS要求を追加しない。依存ソースのSHA256不一致でビルド失敗。
- GPS/センサーはAndroidの同じboot内単調時計を使用。GPS epoch時計との残差、wall時計アンカーの不確かさ、Nativeシリアライズ→JS経由bridge到着時間を区別する。ナノ秒単位は物理同期精度の保証ではない。
- 専用noBackupディレクトリとKeystore alias、AES-GCM、フレーム連番/ハッシュ鎖/ENDによるseal。既存診断を移動・削除しない。
- 16MiB/セッション・64MiB/専用ストア・512KiB pending上限・writer滞留10秒上限。容量や書込み失敗はセンサー診断のみ終了。RUNは継続。
- 上限95分。元GPS診断終了/失敗・通常RUN終了でもセンサーだけを閉じる。Auto Stop中は採取を続ける。プロセス死ではENDがなく不完全記録になる。
- 既存のlocation FGSと同一プロセスで採取。新FGS、センサー用wakelock、マイク/身体センサー権限、GPS設定変更なし。

## 5条件ラベル

別の「5条件マーカー」モードを追加し、既存STOP/RESUMEモードは維持。
センサー診断RECORDINGかつ通常RUN開始後だけ、OpenComm2の各押下をBEGIN/ENDとして対応付ける。

順序は **直立→足プラプラ→その場で弾む→歩行→走行Uターン→走行Uターン→歩行→その場で弾む→足プラプラ→直立**。
各区間2押下、合計20押下。歩行/Uターンは停止せず、試験区間の境界を押す。
本人申告ラベルであり、センサーやAuto Stopから正解を生成しない。押し忘れ・切断・反応/配送誤差は実走後に確認する。

## 机上検証

- JS 74 suites / 553件、Native 102件、SQLite 15件成功。型チェック/Lint成功。
- 両センサー25Hz・95分相当285,000サンプル、GPSリンク5,700件と付随メタデータの合成ファイルを16MiB内に保存し、全フレーム認証・件数・END一致。
- 暗号改変/欠落/件数不整合を拒否。容量超過時に既存ファイルを削除せず、不完全ENDを保存。
- sensor bridge拒否/不在で通常GPSの保存・状態を維持。Production/Pace/debugのNative開始を拒否。
- Native時計パッチは版/ソースハッシュ固定・冪等。通常ビルドではパッチを実行しない。

## 操作案（実機検証後に確定）

1. Auto Stop Diagnostics上部で元GPS診断をARMED。
2. 「加速度・ジャイロ診断」で装着位置を選び、次のRUNをARMED。
3. マーカー画面で「5条件マーカー開始」。開始音を確認してラン画面へ戻る。
4. **通常STARTを押す**。各試験区間の開始/終了でShokzを短く1回。
5. 通常RUNを終了・保存確認後、マーカーのみ終了。元データを削除せず回収する。
